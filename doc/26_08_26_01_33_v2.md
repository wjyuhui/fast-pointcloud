# V2 标量遍历融合方案

本文只规划 `cloud_workspace_node` 的 V2 标量遍历融合，不包含 OpenMP、NEON、VoxelGrid 算法替换或 ROS 2 通信优化。

当前可对照的实测结果：


| 版本        | Core p95 | Voxel p95 | Callback p95 |
| --------- | -------- | --------- | ------------ |
| V0 原始多遍处理 | 9.385 ms | 5.695 ms  | 15.200 ms    |
| V1 射线缓存   | 8.877 ms | 5.515 ms  | 14.286 ms    |


V2 必须在 V1 射线缓存基础上开发，并保持相同输入、参数、输出语义和评测口径。

## 一、逻辑方案

### 1.1 详细方案

#### 1.1.1 目标

将当前以下四段数据处理融合为一次标量深度图遍历：

1. 深度图稀疏采样与反投影；
2. 相机光学坐标系到 `target_frame` 的逐点 Transform；
3. `target_frame` 下的 x 方向 ROI 裁剪；
4. `target_frame` 下的 z 方向 ROI 裁剪。

V2 的目标数据流：

```text
每帧查询一次 TF
        ↓
单次遍历 Depth
  ├── 按 stride 读取深度
  ├── 深度有效性判断
  ├── 使用 V1 射线缓存反投影
  ├── 直接变换到 target_frame
  ├── 在 target_frame 下判断 x/z ROI
  └── 只写入最终保留点
        ↓
VoxelGrid
        ↓
PointCloud2 转换与发布
```



#### 1.1.2 当前问题

V1 当前数据流：

```text
Depth
  → cloud_cam
  → cloud_base
  → x PassThrough 输出
  → z PassThrough 输出
  → cloud_cut
  → cloud_voxel
```

主要冗余：

- `cloud_cam`、`cloud_base`、`cloud_cut` 和临时点云的分配；
- 反投影后再次遍历全部有效点完成 Transform；
- x 和 z 两次 `pcl::PassThrough` 分别遍历和写出点云；
- 最终会被 ROI 丢弃的点仍写入一个或多个中间容器；
- 多轮大块内存读写造成缓存和内存带宽开销。

以当前 `1280×720、stride=4` 为例，每帧最多处理 57,600 个采样像素。`pcl::PointXYZ` 通常包含对齐填充，中间点云会产生数 MB 级重复读写。V2 的主要预期收益来自减少这些中间数据移动，而不是减少 VoxelGrid 计算。

#### 1.1.3 融合边界

V2 融合：

- 深度值读取；
- 相机深度范围过滤；
- 射线缓存反投影；
- 逐点坐标变换；
- `target_frame` 下的 x/z ROI 判断；
- 合格点写入。

V2 不融合：

- `tf_buffer_.lookupTransform()`；
- PCL VoxelGrid；
- PCL 到 `sensor_msgs::msg::PointCloud2` 的转换；
- ROS 发布。

“融合 TF”专指融合逐点矩阵计算。`lookupTransform()` 仍然在每帧像素循环外执行一次，绝不能放入像素循环。

#### 1.1.4 算法语义

对每个按 `depth_stride` 采样的像素 `(u,v)`：

1. 读取深度 `z`；
2. 按现有规则过滤非有限值以及 `[min_depth_m, max_depth_m]` 之外的深度；
3. 使用 V1 缓存计算相机坐标：

```text
x_camera = ray_x[u_index] × z
y_camera = ray_y[v_index] × z
z_camera = z
```

1. 使用本帧查询得到的刚体变换计算目标坐标：

```text
x_target = r00*x_camera + r01*y_camera + r02*z_camera + tx
y_target = r10*x_camera + r11*y_camera + r12*z_camera + ty
z_target = r20*x_camera + r21*y_camera + r22*z_camera + tz
```

1. 保持当前 PassThrough 的包含边界语义：

```text
passthrough_x_min <= x_target <= passthrough_x_max
passthrough_z_min <= z_target <= passthrough_z_max
```

1. 只有同时满足条件的点才写入 `cloud_roi`。

当前逻辑没有 y 方向 ROI，V2 不额外增加 y 过滤，避免改变输出语义。

#### 1.1.5 数据结构

V2 只保留两份主要输出点云：

```text
cloud_roi    // 融合循环直接产生，作为 VoxelGrid 输入
cloud_voxel  // VoxelGrid 输出并用于发布
```

删除主链上的：

```text
cloud_cam
cloud_base
两次 PassThrough 的中间输出
tmp
```

`cloud_roi` 在遍历前按最大采样点数 `ray_x_.size() * ray_y_.size()` 执行一次 `reserve()`，最终 `size()` 只包含通过深度和 ROI 过滤的点。

#### 1.1.6 版本隔离

V2 只做标量遍历融合。以下内容留给后续版本：

- V3：OpenMP；
- V4：NEON；
- V5：OpenMP + NEON；
- VoxelGrid 并行化或算法替换；
- TF静态缓存；
- ROS 2 component、intra-process 和消息零拷贝；
- 改变 `depth_stride`、ROI、Voxel leaf 等业务参数。

V2 测试时必须保持：

```yaml
projection_enable_openmp: false
projection_enable_neon: false
```



#### 1.1.7 正确性验收

性能测试前先用同一帧或同一固定 rosbag 片段比较 V1 与 V2：

- 成功/失败帧判定一致；
- ROI 后点数一致；
- VoxelGrid 后点数一致；
- 输出 `frame_id` 和时间戳一致；
- 点坐标绝对误差建议不超过 `1e-5 m`；
- `16UC1/mono16` 与 `32FC1` 均保持原有支持；
- TF查询失败、无 CameraInfo、非法内参和非法图像尺寸时保持原有错误处理；
- 没有新增 NaN、Inf 或越界访问。

正确性对照可以临时同时运行 V1/V2 算法并比较结果，但该模式不能用于性能统计。完成验证后必须关闭双路计算。

#### 1.1.8 性能验收

沿用现有评测口径：

- 丢弃前 30 个成功帧；
- 收集 1000 个成功帧；
- 输出 `core_p95`、`voxel_p95`、`callback_p95`；
- Release 构建；
- 使用相同 rosbag、相同片段和相同参数；
- 测试期间不能出现 rosbag queue starvation；
- 不开启逐帧 DEBUG 日志；
- V1 和 V2 各至少重复 3 轮，降低调频、温度和系统负载造成的偶然波动。

指标解释：

```text
core_p95：融合后的 Depth → 反投影 → 逐点TF → ROI
voxel_p95：保持不变的 PCL VoxelGrid
callback_p95：成功回调开始到 publish() 返回
```

比较公式：

```text
V2 Core 加速比     = 8.877 / V2_core_p95
V2 Callback 加速比 = 14.286 / V2_callback_p95
```

预期现象：

- `core_p95` 稳定下降；
- `callback_p95` 随 Core 下降；
- `voxel_p95` 在输入点数一致时基本稳定；
- Core 降低后，VoxelGrid 很可能成为节点第一大耗时。

若 V2 的多轮结果与 V1 波动区间重叠，则不能宣称遍历融合获得稳定加速，应先检查编译优化、输入点数、残留中间点云或统计边界。

### 1.2 简洁方案

V2 在 V1 射线缓存基础上，将“深度读取、反投影、逐点TF、x/z ROI”放进一个标量循环，只生成 ROI 后的 `cloud_roi`，再保持原有 PCL VoxelGrid、PointCloud2 转换和发布流程不变。

V2 不启用 OpenMP/NEON，不缓存 TF，不改变 stride、ROI 和体素参数。用固定 rosbag 对比 V1/V2 的 `core_p95`、`voxel_p95` 和 `callback_p95`，并以 ROI点数、Voxel点数、坐标误差、header 和异常行为一致作为正确性门槛。

## 二、逻辑方案对应的代码方案



### 2.1 详细方案



#### 2.1.1 回调主流程调整

将 `depthCallback()` 调整为：

```text
1. callback_begin
2. 检查 CameraInfo
3. 确定 optical_frame
4. 查询本帧 TF，得到 Eigen::Affine3d
5. core_begin
6. 检查/更新 V1 射线缓存
7. 调用 depthToWorkspaceScalar() 生成 cloud_roi
8. core_end
9. voxel_begin
10. 对 cloud_roi 执行原有 VoxelGrid
11. voxel_end
12. 转换 PointCloud2 并 publish
13. callback_end
14. recordTiming(core_ms, voxel_ms, callback_ms)
```

TF查询失败、融合输出为空等情况继续提前返回，并且不计入“成功处理并发布的1000帧”。

#### 2.1.2 TF函数改造

将当前同时负责“查询TF + 遍历点云”的 `transformCloud()` 拆成只查询变换的函数，例如：

```cpp
bool lookupTransformMatrix(
  const std::string & frame_in,
  const rclcpp::Time & stamp,
  Eigen::Affine3d & transform,
  double & tf_lookup_ms);
```

行为要求：

- 进入函数时将 `tf_lookup_ms` 置零；
- `frame_in == target_frame_` 时返回单位矩阵；
- 其他情况只调用一次 `tf_buffer_.lookupTransform()`；
- 使用 `tf2::transformToEigen()` 生成 `Eigen::Affine3d`；
- 保留当前超时参数和节流警告；
- 不进行任何逐点处理。

V2 的 Core 计时从 TF 查询完成后开始，不再通过 `core_with_lookup_ms - tf_lookup_ms` 间接扣除查询耗时。

#### 2.1.3 新增融合标量函数

新增标量参考实现，例如：

```cpp
bool depthToWorkspaceScalar(
  const sensor_msgs::msg::Image & depth,
  const Eigen::Affine3d & transform,
  CloudT & cloud_roi);
```

函数内部步骤：

1. 一次性读取 `stride`、深度上下限、ROI上下限；
2. 检查图像宽高、data、step、内参和射线缓存；
3. `cloud_roi.clear()` 并一次 `reserve()`；
4. 在循环外提取 3×4 变换矩阵系数；
5. 针对 `16UC1/mono16` 执行一套标量循环；
6. 针对 `32FC1` 执行同语义标量循环；
7. 每个像素依次完成深度过滤、射线反投影、矩阵变换、ROI和条件写入；
8. 设置 `width/height/is_dense`；
9. 输出为空时返回 `false`。

逐点计算建议直接使用提前提取的矩阵系数，不在循环中反复构造 `Eigen::Vector3d`：

```cpp
const double x_camera = static_cast<double>(ray_x_[ui]) * z;
const double y_camera = static_cast<double>(ray_y_[vi]) * z;
const double z_camera = z;

const float x_target = static_cast<float>(
  r00 * x_camera + r01 * y_camera + r02 * z_camera + tx);
const float y_target = static_cast<float>(
  r10 * x_camera + r11 * y_camera + r12 * z_camera + ty);
const float z_target = static_cast<float>(
  r20 * x_camera + r21 * y_camera + r22 * z_camera + tz);
```

ROI判断后使用普通标量 `push_back()`。V2 不为后续 OpenMP 提前引入线程局部数组，避免把并行数据结构开销混入标量结果。

#### 2.1.4 参数读取

以下参数在每帧融合循环开始前读取一次，不能在像素循环内读取：

```text
depth_stride
min_depth_m
max_depth_m
passthrough_x_min
passthrough_x_max
passthrough_z_min
passthrough_z_max
```

`voxel_leaf_m` 仍在 VoxelGrid 阶段读取。V2 不改变现有参数名称和 YAML 配置。

#### 2.1.5 VoxelGrid保持不变

Voxel阶段只把输入从 `cloud_cut` 改为 `cloud_roi`：

```cpp
vg.setInputCloud(cloud_roi);
```

以下内容保持不变：

- `pcl::VoxelGrid<PointT>`；
- `voxel_leaf_m`；
- `cloud_voxel` 输出；
- `voxel_begin/voxel_end` 计时边界。

这样 V1/V2 的 `voxel_p95` 才具有可比性。

#### 2.1.6 清理旧路径

正确性验证完成后，正式 V2 应删除或停用：

- `depthToCloudSparse()` 的旧点云生成路径；
- `transformCloud()` 的逐点遍历逻辑；
- 两段 `pcl::PassThrough`；
- `cloud_cam`、`cloud_base`、`tmp` 等中间点云；
- 不再使用后移除 `#include <pcl/filters/passthrough.h>`。

历史 V1 由 Git提交或标签保留，不在正式 V2 中长期保留不可达的重复实现。若暂时增加双路正确性验证代码，应在性能测试前关闭或删除。

#### 2.1.7 计时与日志

保留现有三个统计数组和 p95 逻辑，修改版本标签：

```text
PERF V2 samples=1000 core_p95=... voxel_p95=... callback_p95=...
```

计时边界：

```cpp
lookupTransformMatrix(...);  // 不属于 core

const auto core_begin = std::chrono::steady_clock::now();
depthToWorkspaceScalar(...);
const auto core_end = std::chrono::steady_clock::now();

const auto voxel_begin = std::chrono::steady_clock::now();
// VoxelGrid
const auto voxel_end = std::chrono::steady_clock::now();
```

`callback_p95` 仍从回调入口统计到 `publish()` 返回。不要逐帧打印耗时。

#### 2.1.8 正确性辅助统计

正确性验证阶段临时记录：

```text
sampled_pixels
valid_depth_points
roi_points
voxel_points
```

至少确认相同输入下 V1/V2 的 `roi_points` 和 `voxel_points` 一致。逐帧辅助日志在正式性能测试前关闭，避免扰动 p95。

#### 2.1.9 构建和测试步骤

1. 保持 OpenMP/NEON 参数关闭；
2. 使用 Release 构建 `rgbd_pcl`；
3. 先播放固定短片段验证输出点数和坐标；
4. 检查无 TF错误、越界、NaN和崩溃；
5. 使用与 V1 相同 rosbag 和参数完成 1000 帧统计；
6. 至少执行 3 轮 V2，记录三轮 p95；
7. 与 V1 的多轮数据比较；
8. 测试过程中一旦出现 rosbag starvation，该轮结果作废；
9. 保存版本、构建类型、参数、线程配置、温度/CPU状态和结果。



#### 2.1.10 完成标准

V2 完成必须同时满足：

- 反投影、逐点TF和ROI确实只有一次主遍历；
- 正式路径不再生成 `cloud_cam/cloud_base/PassThrough tmp`；
- V1/V2输出语义一致；
- VoxelGrid算法和参数未变化；
- OpenMP和NEON保持关闭；
- 三项p95统计正常输出且标签为V2；
- 多轮结果显示 Core/Callback 存在可复现下降，或明确记录“未获得超出噪声的收益”；
- 代码能够作为 V3 OpenMP、V4 NEON 和 V5组合版本的标量正确性参考。



### 2.2 简洁方案

1. 把 `transformCloud()` 拆成只返回 `Eigen::Affine3d` 的每帧TF查询函数；
2. 新增 `depthToWorkspaceScalar()`；
3. 在一个标量深度循环中完成深度过滤、V1射线反投影、逐点矩阵变换和x/z ROI；
4. 直接生成 `cloud_roi`，删除 `cloud_cam`、`cloud_base`、两次 PassThrough 和临时点云；
5. VoxelGrid只把输入替换为 `cloud_roi`，其他逻辑不变；
6. Core计时包围融合函数且排除TF查询，Voxel和Callback计时保持原口径；
7. 修改性能标签为V2，用相同rosbag统计1000帧p95并重复至少3轮；
8. 以点数、坐标、header和异常行为一致作为正确性门槛；
9. V2不开OpenMP和NEON，作为后续并行与向量化版本的标量参考。
